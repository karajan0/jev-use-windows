앱 자체가 12개 실제 값을 모두 비교한 경우에만 `Saved 12 fields`를 표시합니다.
설치된 `jev.cmd`를 사용했으며 각 실행마다 새 fixture 프로세스를 시작하고 종료했습니다.
세 쌍을 A/B, B/A, A/B 순으로 실행했습니다. 초기 앱 실행 시간은 제외하고 CLI 시작부터
JSON 결과 반환까지의 시간을 측정했습니다. 사람이 조작한 대조군은 측정하지 않았습니다.

임의 앱이나 사람 대비 속도로 일반화하지 않습니다. 이전 화면 인식 실험의 실패율이
이번 속도 개선으로 해결됐다는 의미도 아닙니다.

같은 목표 문구와 입력값을 사용했습니다. 수정 버전에는 그 목표의 Save 버튼을
`--click Save`로 명시해 모델 선택을 생략했습니다. 이 기능은 알려진 작업 순서에
적합하며, 새로운 화면을 스스로 해석하는 모델 성능 향상을 뜻하지 않습니다.

## 적용 사항

- 지원되는 네이티브 편집 필드는 UI Automation ValuePattern으로 직접 설정하고
  같은 provider에서 정확한 값을 읽어 확인합니다. 보호/읽기 전용 입력을 거부합니다.
- 한 관찰에서 이미 확인된 명시적 필드들을 연속 처리합니다. 각 입력 전 전경 창,
  창 위치, 컨트롤의 이름·위치·runtime identity를 다시 확인합니다. 값 검증 실패는
  저장 전에 중단합니다. 다음 필드가 바뀌었다면 입력 전에 묶음을 끝내고 재관찰합니다.
- `--click EXACT_LABEL`을 반복해 명시적인 버튼 순서를 지정할 수 있습니다.
  누락·중복 라벨을 추측하지 않으며 매 단계 실제 대상을 검증합니다.
- 입력 직후 바로 관찰합니다. 상태가 이미 바뀌었다면 기존 대기 시간을 생략하고,
  아직 반응하지 않았으면 기존 제한 시간 안에서 변화 감지 후 재관찰합니다.
- 고해상도 OCR의 2배 확대 타일 결과를 정확한 픽셀 해시·크기·모드·언어로 캐시합니다.
  스레드별 최대 64개이며 화면 이미지를 보관하지 않고 OCR 결과만 보관합니다.
- 이웃 3개를 구할 때 전체 정렬 대신 부분 선택을 하고, 후보 점수의 공통 가중치
  계산을 후보별 반복문 밖으로 이동했습니다.

## 정확성 및 실패 처리

최초 키보드 기반 연속 입력 시험은 10번째 필드 읽기 검증에서 실패했고 저장 전에
중단됐습니다. 원본 로그 `runs/speed-task-ab.json`을 보존했습니다. 이후 지원되는
네이티브 필드에 직접 값 설정을 적용한 것이 최종 성공 3쌍 결과입니다.
API로 이미 입력을 보낸 후 오류가 나면 키보드로 재전송하지 않습니다.
작업 시작 전부터 보이던 완료 문구만으로 새 클릭 작업의 성공을 인정하지 않습니다.

96개 테스트 통과. 추가 검증에는 느린 UI의 재관찰, 클릭 라벨 중복 거부, 네이티브
필드 연속 입력, 값 검증 실패 시 저장 금지, 읽기 전용 거부, 입력 오류 후 재전송 금지,
타일 캐시의 픽셀·언어 변경 무효화 및 정리가 포함됩니다.
