# 화면 인식 수정 및 재검증 — 2026-09-23

## 적용한 수정

1. **고해상도 OCR**: 긴 변 1800px 초과 화면을 768px 코어와 48px 겹침 영역으로
   나누고 2배 확대 인식합니다. 각 단어 중심이 속한 코어에서만 결과를 수집해 경계
   중복을 방지합니다. 작은 창은 기존 단일 OCR 경로를 유지합니다.
2. **후보 누락 수정**: 관찰 단계의 앞쪽 OCR 70개 / 전체 140개 자르기를 제거했습니다.
   모델 입력에는 지시문과의 토큰 관련도·희소성, 실제 라벨 일치, 초점 상태로 고른
   후보 112개와 공간적으로 분산한 후보 최대 28개를 전달합니다.
3. **그림으로 그려진 조작점**: UIA 조작점이 8개 미만인 창에서 OCR 영역을 제외한
   작은 윤곽 성분을 찾습니다. X/꺾쇠/삼각형/더하기는 생성한 기하 도형과 비교하고,
   나머지는 의미를 추측하지 않고 이름 없는 시각 후보로 남깁니다. 주변 문구와 방향,
   거리를 제공하며 원래의 입력 직전 픽셀 검증을 적용합니다.
4. **모델 결정 일관성**: 서로의 답을 참조하던 동작 종류 / 클릭 대상 / 입력 대상
   질문을 구체적 동작 ID 하나를 선택하는 질문으로 통합했습니다. 완료 증거는 별도
   질문과 기존 결정적 검증으로 유지합니다.

정답 좌표, 특정 앱 이름, 벤치마크 문제 문구를 런타임 코드에 넣지 않았습니다.

## 고정 데이터 재시험

원본 데이터 및 채점 기준은 [최초 보고서](SCREENSPOT_PRO_REPORT.md)를 따릅니다.
유효 클릭 신뢰도 기준 0.35와 문항당 모델 호출 1회는 유지했습니다.

| 표본 | 기존 버전 | 최종 수정 버전 |
|---|---:|---:|
| 기존 고난도 32문제 | 0/32 | 4/32 |
| 기존 고난도에서 모델에 제공된 정답 위치 후보 존재 | 1/32 | 12/32 |
| 미사용 스크린샷 32문제 | 1/32 | 6/32 |
| 미사용 표본에서 정답 위치 후보 존재 | 2/32 | 9/32 |

고난도 최종 결과는 icon 1/16, text 3/16입니다. Unreal Engine 재생 아이콘,
Photoshop File/Edit 메뉴, Premiere 효과 펼치기를 맞혔습니다.
미사용 표본 최종 결과는 icon 0/16, text 6/16입니다. 모든 평가 실행에서 API 오류는 0건입니다.
비율은 소표본 단일 실행 결과이며 전체 ScreenSpot-Pro 점수로 해석할 수 없습니다.

미사용 표본은 수정 중간에 **예측 실행 전에 고정**했습니다. 앱별로 기존 고난도 및
큰 영역 대조군에 나온 모든 이미지 파일을 제외하고, 각 유형의 남은 문항을 SHA256(ID)
순으로 정렬하여 2개씩 선택했습니다. 기존 버전과 수정 버전은 동일한 이 32개를
각각 한 번 평가했습니다. 이 결과를 확인한 뒤 런타임을 추가 튜닝하지 않았습니다.
최초 32문제는 개발 중 재사용했으므로 그 결과만으로 일반화를 주장하지 않습니다.

고난도 수정 버전 관찰 중앙값은 1169.266ms, 결정 중앙값은 341.346ms입니다.
미사용 표본의 관찰 중앙값은 기존 172.727ms → 수정 1172.519ms,
결정 중앙값은 268.433ms → 324.625ms였습니다. 정밀 인식에 계산 비용이 증가했습니다.
두 미사용 표본 평가는 순서대로 실행했습니다. 전체 작업 시간과는 다른 측정입니다.

## 실제 Windows 테스트

모든 입력은 설치된 `jev.cmd run`으로 실행했습니다. 테스트용 WinForms 앱은
명령 실행 및 성공 판정용 화면만 제공하며 자동 클릭을 수행하지 않습니다.

| 테스트 | 결과 | Jev 보고 시간 |
|---|---|---:|
| 한국어 입력 → Save → 상태 문구 확인 | goal_achieved=true | 2.035s |
| 90개 항목 아래 Draft 오른쪽 작은 X 아이콘 클릭, 참조 이미지 없음 | goal_achieved=true | 1.641s |
| 배경 애니메이션과 이동 기능이 있는 참조 아이콘 클릭 | goal_achieved=true | 1.320s |

세 실행 모두 모델 호출 1회입니다. 새 시각 후보를 통한 실제 클릭 로그는
`Click Visual 'X-shaped close icon' (right of 'Draft' (57px); ...)`였으며
`Closed successfully`로 검증됐습니다. 이동 fixture 실행 중 반드시 대상 재탐색이
발생했다고 주장하지 않습니다. 테스트 후 생성한 fixture 프로세스만 종료했습니다.

  해결된 것은 아니며, 정적 화면 평가가 실제 다단계 작업 성능을 보장하지 않습니다.
