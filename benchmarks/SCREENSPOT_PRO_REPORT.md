# ScreenSpot-Pro 고난도 실측 — 2026-09-23

현재 설치된 Jev의 OCR 및 모델 선택 경로로 공개 ScreenSpot-Pro 데이터를 평가했습니다.
고난도 표본의 정답률은 **0/32**, 큰 영역 대조군은 **0/8**입니다. API 오류는 0건입니다.
이 결과는 공식 전체 데이터셋 점수나 실제 앱의 다단계 작업 성공률이 아닙니다.

## 데이터와 평가 조건

- 원본: https://huggingface.co/datasets/likaixin/ScreenSpot-Pro
- 고정 리비전: `210e78d3844251110bff86c95835ebd37a6930fa`
- 공식 평가 코드: https://github.com/likaixin2000/ScreenSpot-Pro-GUI-Grounding/blob/main/eval_screenspot_pro.py
- 앱: AutoCAD, Blender, Inventor, Photoshop, Premiere, SolidWorks, Unreal Engine, Vivado.
- 고난도: 앱마다 데이터셋 분류상 icon/text 각각 상대 면적이 가장 작은 2문제.
  동률은 ID로 정렬했습니다. 결과를 본 뒤 표본을 교체하지 않았습니다.
- 대조군: 같은 앱마다 데이터셋 분류상 text 중 상대 면적이 가장 큰 1문제.
  큰 영역이 쉬운 의미 이해를 보장하지 않으므로, 쉬운 문제의 대표 표본은 아닙니다.
- 원본 화면 크기: 2560×1440, 3840×1080, 3840×2160.
- 원본 이미지와 영어 지시문만 예측 함수에 전달했습니다.
  정답 bbox는 표본 선정과 예측 이후 채점에만 사용했습니다.
- 정답에서 자른 참조 이미지나 수동 정답 힌트를 제공하지 않았습니다.
- 정적 이미지 데이터에는 UIA 트리가 없으므로 UIA 결과만 빈 값으로 대체했습니다.
  실제 `desktop._finish_observation`, `runner._actions`, `runner._choose`를 사용했습니다.
- OCR 언어는 en-US, 기본 후보 상한 70개, 클릭 신뢰도 기준은 기존 0.35입니다.
  모델 호출은 문항당 1회이며 라이브 실행 루프의 재관찰/재시도는 포함하지 않습니다.
- 선택한 클릭 중심이 공식 bbox 안에 들어가면 정답입니다. 클릭 이외의 응답과
  신뢰도 미달은 실패입니다. 신뢰도 필터 전 좌표도 고난도/대조군 모두 정답 0개입니다.
- 실제 데스크톱 클릭은 실행하지 않았습니다. 데이터셋은 드래그 등의 지시도 대상
  위치 찾기로 평가하므로, 어댑터 역시 원문 지시를 단일 대상 클릭 위치 문제로 감쌌습니다.

## 결과

| 평가 | 정답 | 정답 위치의 후보가 존재한 문항 | API/실행 오류 |
|---|---:|---:|---:|
| 고난도 icon | 0/16 | 전체 아래 참조 | 0 |
| 고난도 text | 0/16 | 전체 아래 참조 | 0 |
| 고난도 전체 | 0/32 | 1/32 | 0 |
| 큰 영역 text 대조군 | 0/8 | 0/8 | 0 |

고난도 31문제에서는 전체 OCR 출력에도 정답 bbox 안의 중심점을 갖는 단어가 없었습니다.
나머지 1문제는 후보가 있었지만 올바른 선택으로 이어지지 않았습니다.
대조군 1문제는 전체 OCR 출력에 정답 위치 후보가 있었지만 70개 상한에서 제외됐습니다.
`perception` 분류는 후보 중심점 도달 가능성에 기반한 진단이며, 사람 수준의 원인 판정을
대체하지 않습니다. 인접한 글자를 알아도 작은 화살표나 핸들에 클릭점을 놓지 못할 수 있습니다.

고난도 관찰 시간 중앙값은 180.553ms, 모델 결정 시간 중앙값은 286.596ms였습니다.
대조군 시간은 각각 211.269ms, 311.251ms였습니다. 네트워크 변동이 있고 대조군은
OCR 진단과 동시에 실행했으므로 두 그룹의 시간 차이를 성능 차이로 해석하지 않습니다.

## 원인 분리 실험

설치된 OCR 구현은 긴 변을 최대 1800px로 축소합니다. 예를 들어 3840px 화면에서
원래 높이 14px인 글자는 약 6.6px로 줄어듭니다. 실제 Photoshop의 File/Edit 메뉴도
기본 경로에서는 후보가 생기지 않았습니다.

같은 32장을 1000px 단위로 나누고 경계에 64px 문맥을 추가해 원본 해상도에서 OCR을
수행했습니다. 타일 선택에 정답을 사용하지 않았으며, 모델 호출은 하지 않았습니다.

- 전체 OCR의 정답 위치 도달 가능 문항: 기본 **1/32**, 분할 **3/32**.
- 기본에서 가능했던 1문항은 분할에서 사라졌고, 새로 3문항이 가능해졌습니다.
  따라서 모든 표본에서 단조롭게 개선된 것은 아닙니다.
- 분할 OCR 시간 중앙값: **275.466ms**. 타일 결합과 OCR만 포함하므로 기본 관찰
  전체 시간과 엄밀한 동등 비교가 아닙니다.
- 이 수치는 정답 후보 존재 여부입니다. **실제 정답률 3/32로 보고하지 않습니다.**
- 후보 상한도 적용하지 않은 진단이므로 운영 경로에 바로 적용한 결과가 아닙니다.

## 판단

현재의 참조 이미지·OCR 중심 구조는 낯선 전문 UI의 작은 아이콘과 연결점에 취약합니다.
기존 77개 회귀 테스트 통과는 이 범용 화면 이해 능력을 입증하지 않습니다.

다음 개선은 원본 해상도를 보존하는 선택적 OCR, 목표에 따른 후보 선별,
텍스트 없는 조작 대상의 시각적 검출과 의미 판단, 텍스트와 인접 아이콘의 관계 해석에
집중해야 합니다. 이번 표본을 본 후 튜닝한다면 평가용으로는 별도 미사용 표본을 고정해야 합니다.
현재 어댑터는 UIA가 없는 조건이므로, UIA가 풍부한 실제 앱에 동일 실패율을 적용할 수 없습니다.

WindowsAgentArena도 검토했습니다. 공식 환경은 Docker와 준비된 Windows VM이 필요하며,
현재 PATH에 Docker가 없어 이번에는 실행하지 않았습니다. 설치·실행했다고 주장하지 않습니다.
공식 안내: https://github.com/microsoft/WindowsAgentArena

각 디렉터리에 manifest.json, results.json, summary.json, 원본 이미지가 있습니다.
고난도 디렉터리에는 이미지별 SHA256을 포함한 results.json, code-hashes.json 및
tiled-ocr-diagnostic.json도 보존했습니다. 키나 인증 헤더는 결과에 기록하지 않았습니다.
런타임 코드와 모델을 이 표본에 맞춰 수정하지 않고 평가했습니다.
